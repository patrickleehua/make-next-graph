# MVP 验收范围

目标：以轻量 skill 指导已有 coding agent 围绕真实产物持续推进任务；能独立使用，
能组合所选 SDD 与简易 TDD，稳定处理失败、修改和接续。下表是交付验收范围，
不使用代码覆盖率或主观百分比代替完成度。

| 项 | 实际要证明的行为 | 所需证据 |
|---|---|---|
| 1 | 以目标和真实依赖求下一步，读取不改产物，不保存节点状态。 | 真实 CLI 与核心回归。 |
| 2 | 缺失、未知、失败、未验证分别处理，不把已有最终文件当作通过。 | 失败与依赖链回归。 |
| 3 | 中断后重读产物并接续，昂贵数据不重复采集。 | 跨进程示范与快照复用实测。 |
| 4 | 上游改变仅提示影响，agent 按实质判断必要工作。 | 影响提示与保留既有成果回归。 |
| 5 | 直接引用 OpenSpec 的原始产物，沿它的原生流程工作。 | 原生工具初始化、规格校验、引用及 TDD 实跑。 |
| 6 | 直接引用 Spec Kit 的原始产物，沿它的原生流程工作。 | 原生工具生成结构、引用及 TDD 实跑。 |
| 7 | 简易 TDD 以验收写测试、真实 red、实现、green 和相关重构复查推进。 | 测试先于对应实现，保存红绿命令原文，并实际运行最终产物。 |
| 8 | 行业可添加中间产物，不改核心；并行仅给依赖独立候选。 | 组合模板、插入节点和候选回归。 |
| 9 | 一个互联网案例可用；旧绿结果不能掩盖后来的坏产物。 | 真实联网产物、破坏与修复回归。 |
| 10 | skill 单独复制可用，零运行依赖，公开内容不带私有项目资料。 | 脱离仓库运行、Node 22/24、格式与公开目录检查。 |

保持四个 CLI 动作：`init`、`next`、`validate`、`mermaid`。可选命令采集器只是
原生进程的输出工具，不增加工作流运行时。SDD 接入只引用文件，不建立另一套工具
状态、命令编排、规则注册或必填账本。新增指导优先写在现有 skill 和方法参考中。

长时间工作的执行、唤醒、停止、授权、冲突协调继续由宿主承担。本 MVP 验证
文件与进程层接续和实际任务推进，不把它宣传为跨宿主无人值守可靠性认证。
