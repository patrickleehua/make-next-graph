# 收益、可观察现象与证据

当前可确认的价值是：成果能够复用，缺口可以定位，新 agent 能从文件继续，独立路径可以交给宿主分工。
总体速度、成本与质量提升要在真实业务中测量，不能从图存在或测试全过直接推出。

## 已观察到的现象

以下结果来自 [十轮验证记录](verification.md)；测试与场景主要在 Windows 环境运行。

| 收益方向 | 可以看到的实际现象 | 已有证据 | 解释范围 |
|---|---|---|---|
| 复用成果 | 下一进程继续时快照字节和修改时间不变。 | 联网/离线示范跨进程续跑。 | 证明该案例复用了资料，不代表所有任务都不会重做。 |
| 交接更可检查 | 新 agent 保留原目标、测试和 red，补实现后原测试全部通过。 | 受控 TDD 交接，10 项测试由真实失败转为通过。 | 存在持久文件与交接说明；不是任意进程崩溃恢复证明。 |
| 缺口更清楚 | 最终文件已存在，必要前置缺失或失败时仍不可用。 | 依赖闭包、失败与未知证据回归。 | 只证明所建依赖的机械判断，完整性取决于图和验收。 |
| 可以分工 | 两位 agent 写各自输出，宿主读取后整合，原输入未变。 | 两条独立文档分析路径实际执行。 | 输出互不重叠；竞争写入协调仍属宿主。 |
| 可适应变化 | 新目标出现后补出有效失败，修复后新测试通过，旧证据仍在。 | 保留时间戳和旧 green 的目标变更场景。 | 正确判断来自 agent 重读目标，时间戳没有自动识别内容变化。 |
| 可单独使用 | 三节点完成有来源的文档建议，无软件阶段。 | 独立文档任务。 | 资料是合成记录，不代表真实行业交付质量已获认证。 |
| 可组合原生方法 | 图引用原规格路径，真实 red/green 与程序运行结果留下。 | OpenSpec、Spec Kit 接入场景。 | 文件级组合与运行事实，原生工具全流程范围另见原验证记录。 |

## 尚不能承诺的收益

| 说法 | 当前状态 |
|---|---|
| 比普通 agent 的成果质量更高 | 一组弱提示对照中，两种方式都通过了独立行为检查，没有证明因果提升。 |
| 节省固定比例的时间或 token | 没有足够的同目标对照和总成本记录。 |
| 并行会按 agent 数量倍速 | 没有证据；整合成本和资源争用可能抵消收益。 |
| 能长期无人值守直到成功 | 宿主唤醒、取消、预算和外部动作恢复尚未由本工具提供或验证。 |
| 文件齐备就说明业务完成 | 内容、测试覆盖和专业验收仍需要判断。 |

本机一轮查询抽样中位约 55–56 ms，只是该版本、该图、该 Windows 环境的命令调用成本；
不能用它代替任务总耗时或其他机器的性能承诺。

## 在自己业务里怎么测

选择相同目标、输入、模型、工具和验收标准，对照普通流程与 make 流程。先固定验收，再比较过程。

| 观察项 | 怎样记录 | 什么现象支持收益 |
|---|---|---|
| 结果质量 | 用同一组验收条件，由独立人员或检查程序评估。 | 通过率、遗漏或返工有可重复差异。 |
| 重复劳动 | 记录重复采集、重写有效产物、重复运行相同检查的次数与原因。 | 无必要的重做减少。 |
| 接续投入 | 在同一实际交接点换新会话，记录补问、重规划与恢复到有用行动的投入。 | 同样质量下接手成本降低。 |
| 总时间 | 包括建图、查询、执行、内容检查、整合与返修。 | 总交付更快，而非只某一步变快。 |
| 模型成本 | 从宿主实际用量记录取 token 和费用；缺数据就留未知。 | 同样质量下总成本减少。 |
| 并行收益 | 同目标比较顺序/并行，计入资源等待和整合。 | 总交付时间下降且结果无退化。 |

这些是建议的测量方式，不是已经达成的指标。不必额外建设状态台账；复用宿主用量和必要任务证据即可。

## 什么时候更值得用

适合有资料复用、多阶段成果、跨会话接续或独立分工的任务。一次能直接完成的小改动，建图可能没有额外收益。
