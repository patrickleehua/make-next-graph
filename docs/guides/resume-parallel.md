# 接续、变更与并行分工

接续依赖可读取的真实成果。宿主负责再次启动和授权，make 帮助新一轮执行定位缺口。

## 新 agent 怎么接手

交接以下材料即可开始，不必把所有历史对话塞进上下文：

| 材料 | 解决什么问题 |
|---|---|
| 当前目标与验收要求 | 这次到底交付什么。 |
| 实例化 graph | 成果之间依赖什么。 |
| 相关已有产物 | 可以复用什么，内容质量如何。 |
| 原始检查输出 | 什么实际跑过，失败原因是什么。 |
| 必要交接说明 | 未决判断、暂停意图、外部动作和当前边界。 |

给接手 agent 的提示可以是：

```text
使用 $make-next-graph 按当前目标继续。
先读 goal、graph 和相关已有产物，复用有效成果，确认实际缺口后执行。
保留真实检查和仍有价值的历史输出，按当前目标交付。
```

在仓库示例里，下一进程可以直接重算：

```sh
node skills/make-next-graph/scripts/make.mjs next .work/quickstart/graph.json --json
```

`ready` 为空时还要看 attention、waiting 和目标内容。缺输入、未知证据、无执行条件都可能没有 ready。

## 目标改变怎么办

例如验收规则从旧阈值改成新阈值：

1. 读新目标，比较实际规格、实现、测试和最终成果。
2. 保留仍有效的资料和行为；新增或调整受影响的断言。
3. 先观察真实失败，修复实际原因，再运行对应验证。
4. 必要时更新图引用或依赖，使用 `changeReason` 说明原因。
5. 阅读最终内容后交付。

时间影响是建议，不是自动失效。内容变化但时间戳保留时，图可能没有提示；读目标与内容仍是接续的一部分。
普通评审文件写着“不通过”也可能为 present，应处理实际意见。

## 给多个 agent 分配独立路径

联网示范的快照齐备后，ranking 和 coverage 是两个独立候选。可分别交给宿主的原生子 agent：

```text
Agent A
输入：目标、sources/snapshot.json
输出：analysis/ranking.json
验收：按保存分数降序，分数相同按 ID 升序，不重抓数据。

Agent B
输入：目标、sources/snapshot.json
输出：analysis/coverage.json
验收：从同一快照统计返回条目和来源 host，不探测实时可达性。
```

宿主收回两份真实文件、读内容后再整合摘要。每位 agent 只需自己的必要输入和输出边界。

`parallelCandidates` 只表示依赖独立。两条路径可能修改同一文件、共享代码或触发同一外部动作；
宿主仍需安排输出归属、目录隔离和合并。`recipe.writes` 是范围提示，没有文件锁。

## 停止和外部动作

没有有用行动时，说明具体缺少的输入、证据或决策并让出执行。唤醒、预算、暂停和取消由宿主保留。

发送、发布等动作被中断后，先核对实际执行事实和操作的重试/幂等契约；文件缺失不能证明动作未发生。
不要因图里缺文件就重复外发。依赖仍独立的内部工作可以继续。

依赖图保持无环。返修属于宿主循环：读评审、改草稿、重新检查；需要留每版时增加有意义的新版本产物。
